# UI/UX 与操作闭环收口说明

本轮从最新 `main` 建立独立分支，目标是修复 M5-D 合并后仍存在的前端产品化问题，不新增后端业务语义。

## 设计原则

- 编辑工作台与运维配置台使用不同页面宽度模式；
- 1920/2048 宽屏下充分利用空间，同时避免无限拉伸；
- Event Workbench / Candidates 使用稳定右侧操作栏；
- 日常页面以列表和状态为主，新建/编辑进入右侧抽屉，不再长期把原始字段表单铺在页面顶部；
- 一个业务区域只突出一个主要动作，低频/危险动作降级；
- 写操作继续调用既有 API，保留 Actor、Risk Gate、confirmation、Publication 等既有语义；
- 无真实后端能力的操作不伪造。

## 本轮重点页面

- 连接器实例：列表优先，新建/编辑抽屉，测试运行/立即执行保留真实接口，并明确无信源前置条件；
- 信源：列表优先，新建/编辑抽屉，测试运行后可继续查看运行记录；
- 采集任务：创建流程改为抽屉，列表直接提供立即运行与暂停/恢复；
- AI 服务商 / 模型：创建、凭据更换改为抽屉；连接测试不再使用浏览器 alert；
- AI 路由：从“表格内直接编辑全部字段”改为“当前版本列表 + 配置抽屉”；
- AI 预算：创建/调整改为抽屉，移除 `window.prompt` 编辑；
- 发布：发布记录为主，真实发布登记改为显式抽屉任务；
- 效果反馈：表现列表为主，手动录入和 CSV 导入改为独立抽屉流程。

## 布局基准

- Sidebar：约 236px（中等屏幕 220px）；
- Workspace 最大宽度：1760px；
- Operations 最大宽度：1600px；
- Right Rail：380px（中等屏幕 350px）；
- 页面横向留白：28px；
- 正文：14px；
- 控件：40px；
- 主按钮：38px；
- <=1180px 时工作台右栏下移。

## 验证边界

本轮修改以 UI Engineering 与既有 API 操作闭环为主。真实 Candidate、真实平台采集、Production Provider 等仍按 M5-D 的独立验证门槛判断，不因 UI 可操作而自动升级为 PASS。
